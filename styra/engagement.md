# Engagement: Styra AI Fashion Assistant

## 1. What is in scope?

**Proposed scope for the current design cycle:**

- Review existing project research, storyboard, persona, and other discovery artifacts.
- Identify the primary user segment and highest-priority fashion-shopping problem.
- Clarify the intended role of AI in solving that problem.
- Define the initial user journey and MVP boundaries.
- Develop and validate the core flow before committing to detailed UI.
- Consider requirements for Portugal and Bangladesh using available research.

The specific screens and deliverables must be agreed once the existing project materials have been reviewed.

## 2. What is explicitly out?

Until the MVP is defined, the following are not committed deliverables:

- Production-ready AI implementation or backend development.
- Retailer integrations and live product catalogue connections.
- Payment and checkout implementation.
- Virtual try-on or body-visualisation technology.
- Advanced personalisation infrastructure.
- Separate country-specific product builds without supporting evidence.
- Additional features introduced after the agreed design scope.

These items may be considered later if user research and product strategy justify them.

## 3. How many revision rounds, and what counts as one?

**Not yet agreed.**

Proposed boundary: One consolidated feedback round per major design milestone. Changes to the approved target user, core problem, MVP, or user journey should trigger a scope review rather than being treated as minor visual revisions.

The number of rounds should be confirmed before a delivery commitment is made.

## 4. Who signs off, by name?

**Product owner:** Hasina Parvin Deepa — to confirm and document the final approval role for this project.

Research findings, the chosen user problem, the MVP scope, and the core user journey should be approved before detailed UI design proceeds.

If collaborators or external stakeholders are involved, their decision-making and feedback responsibilities must be documented.

## 5. What happens when they ask for something new?

Record the requested change and assess its impact on the user problem, product scope, design work, and timeline.

If the request changes the approved MVP or introduces a new flow, document the change before beginning work. Update the agreed deliverables and schedule where necessary.
